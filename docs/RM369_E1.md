## State contract

Every oriented node has physical row-major child slots 0..8.
Breadth-first integer IDs start at root 0; child ID = 9*parent+1+slot.
A depth-d field contains (9^d-1)/8 orientation nodes and 9^d cells.
Absent keys mean orientation 0. Setting orientation 0 removes a record.
An ancestor orientation alters numeric digit assignments, not physical
descendant addresses. No arbitrary cell writes, permissions or routing.

Read traverses one address path with d dictionary lookups and base-9
accumulation; integer arithmetic costs increase with depth. No dense
allocation and no validation of unrelated records per read. Snapshot
encoding sorts changed keys, so it is not a constant-time operation.
Depth is 1..64, changed-node cap is one million.

## Canonical snapshot RM1

Eight-byte header: ASCII RM1, unsigned one-byte depth, unsigned four-byte
big-endian record count. Each record contains the smallest fixed key
width sufficient for the largest legal node ID (at least one byte),
followed by an unsigned orientation byte 1..7. Keys strictly increase;
zero, duplicate, out-of-range, truncated and trailing records are
rejected. No embedded code or authentication. The generating seed and
orientation ordering are pinned by E0 and the schema version.

## Storage comparison

Two overrides at root and physical child 8 (orientations 1 and 7):

| Depth | Virtual cells | Sparse snapshot bytes | Packed orientation payload bytes | Flat value payload bytes |
| --- | ---: | ---: | ---: | ---: |
| 2 | 81 | 12 | 4 | 81 |
| 4 | 6561 | 14 | 308 | 13122 |
| 12 | 282429536481 | 20 | 13238884523 | 1412147682405 |

Packed orientation baseline uses three bits for every internal node,
rounded up to whole bytes; flat array uses the smallest whole-byte
width that can hold the maximum cell value. Neither includes a header.
Sparse snapshot includes its eight-byte header. The report also emits
the actual JSON byte length of the sorted sparse record array (without
header). These are serialized counts or analytically derived payload
sizes, not allocations, heap measurements or timings. Generator code
and the schema are shared assumptions, not included in any payload.
An ordinary sparse integer map with the same encoding is equivalent:
no special architecture advantage has been established.

Negative control: depth 2 with all ten nodes changed uses 28 snapshot
bytes versus 4 bytes for a packed orientation array. Sparse is not
universally better; dense orientation storage can win. No claim about
arbitrary information compression, neural models, or physical fields.
